## 真正修复：换互操作是误判，根因是 Activate 参数封送（2026-11-01 晚）
- 用户换 2026 互操作重编后仍报 `FIRSTCHANCE COMException E_FAIL`（栈顶 `System.RuntimeType.InvokeMember`，仍是 `Activate` 调用、仍无 `Activate begin`）→ 互操作版本不是根因。

- **根因（.NET 8 comhost 已知坑）**：Inventor 经 IDispatch 调 `Activate` 时，首参声明为嵌入式互操作类型 `Inventor.ApplicationAddInSite`，CLR 的 `InvokeMember` 在参数封送阶段抛 `E_FAIL`，方法体未进。
- **修复（已落地 `StandardAddInServer.vb`）**：

  2. 类改 `Implements IInventorAddInServer`（不再实现 `Inventor.ApplicationAddInServer`）。

  4. `Deactivate`/`Automation`/`ExecuteCommand` 也改 `Implements IInventorAddInServer.*`。

- **代码现状**：保留自定义 dual 接口 `IInventorAddInServer`（IID E3571293、DispId 50336257/58/59/60 与官方一致）；`Activate(addInSiteObject As Inventor.ApplicationAddInSite, firstTime As Boolean)` 用真实互操作类型（已回退 Object 改法）。`Deactivate`/`Automation`/`ExecuteCommand` 同样 `Implements IInventorAddInServer.*`。

## VisibleDocuments vs Documents 的最终结论（2026-11-01 约 15:57）
- 用户反馈：用 `ThisApplication.Documents` 会把装配体**内部自动加载的所有引用零件**都列出来；用户只要"当前打开的零部件"。
- 最终结论：必须用 **`ThisApplication.Documents.VisibleDocuments`**（只包含有窗口、真正被打开的文档）；`Documents` 包含装配体自动加载的引用文档，会"列出所有零部件"。
- 当前实现：`VisibleDocuments` + 排除活动文档（`Is` 与 `FullFileName` 双保险，路径用 `OrdinalIgnoreCase`）+ 名称 `Path.GetFileNameWithoutExtension` + 逐项 `Try/Catch` + 加载后 `ClearSelection → CurrentCell → Selected → ShowSelectedThumbnail()` 显式刷新。
- 编译通过，已部署（GLTool.dll 15:57）。
