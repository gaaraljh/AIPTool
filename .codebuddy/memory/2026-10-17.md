## AIPTool 升级 .NET Framework 4.8 → .NET 8.0（net8.0-windows）

- `AIPTool.vbproj` 重写为 SDK 风格工程，旧版备份 `AIPTool.vbproj.net48.bak`；Debug 仍输出到 `C:\ProgramData\Autodesk\Inventor Addins\AIPTool\`。
- 代码适配：64 个文件共 3558 处 `Windows.Forms.Xxx` → `System.Windows.Forms.Xxx`（.NET 8 的 VB 编译器不再支持经 `Imports System` 解析的半限定名）。过程中踩过两个坑：`Encoding.UTF8.GetString` 不解码 BOM 导致重复 BOM（用字节级修复）；正则 `\bWindows\.Forms\.` 会误匹配 `System.Windows.Forms.` 后缀，需再替换 `System.System.Windows.Forms.` 回来。
- 依赖清理：`stdole` 从 NuGet 包改为直接引用 `library\stdole.dll`（GAC 副本）+ `EmbedInteropTypes`，避免 NuGet 版传递依赖 `Microsoft.VisualStudio.Interop` 等；工程最终 0 个 NuGet 包依赖，输出只剩 AIPTool.dll/comhost/runtimeconfig/deps/pdb。
- COM 注册：.NET 8 不支持 `RegisterForComInterop`，改用 `EnableComHosting` 生成 `AIPTool.comhost.dll` + 仓库内 `RegisterAddin.ps1`（管理员运行，英文编写——含中文的 .ps1 在 PowerShell 5.1 下会因 ANSI 读取而解析失败）。

## 关键坑（重要，勿再犯）

1. **.NET 8 的 comhost 只收录显式 `[ComVisible(True)]` 的类型**：.NET Framework 时代公共类默认对 COM 可见，升级后不标 `ComVisible` 则 comhost 的类清单为空，`DllGetClassObject` 返回 0x80040111(CLASS_E_CLASSNOTAVAILABLE)，Inventor 启动闪屏后直接退出且事件查看器无日志。已在 `StandardAddInServer` 上补 `<ComVisible(True)>`、`<ClassInterface(ClassInterfaceType.None)>`。
2. **comhost 时间戳不可信**：SDK 生成的 comhost 会保留较早时间戳（obj\Debug 里是 10/4），MSBuild 增量复制会判定"未更改"而跳过，导致输出目录残留旧 comhost。已在 vbproj 加 `RefreshComHostInOutput` 目标强制复制。
3. **验证 COM 激活别用 PowerShell 5.1 的 `New-Object -ComObject`**：会走 .NET Framework COM 互操作并报 0x80131165（ Typelib 未注册）。要用原生 COM 客户端验证，例如 `cscript //nologo test.vbs` 里 `CreateObject("InventorAddIn.StandardAddInServer")`。
4. VB 工程 `Namespace InventorAddIn` + `RootNamespace=AIPTool` → 类型全名是 `AIPTool.InventorAddIn.StandardAddInServer`，用 `Assembly.GetType` 查不到时先枚举类型。
5. `C:\ProgramData\...\AIPTool\` 下残留 1 字节 `__write_test.tmp`（工具无法删除），需用户手动删。

## F5 调试闪退（退出码 1、无弹窗、无事件日志）

排查结论与处理：
1. **直接原因**：`StandardAddInServer.Activate` 里同步执行了 UNC 网络检查（`IsFileExists("\\Likai-pc\发行版\更新包\…")`，ConfigFile.ini 的 Server 项），网络不可达时阻塞 **5 秒以上**；整段 Activate 耗时 5.7s。不带调试器能正常起来，**挂上 VS 调试器后启动更慢，触发 Inventor 插件加载超时 → 进程退出码 1**（无弹窗、无事件日志、WER 无记录）。
2. **修复**：把「检查更新 + 下载物料 xlsx/帮助 pdf」移到 `Task.Run` 后台线程；本地路径计算保持同步。Activate 现在 **0.3 秒**返回，后台任务 5 秒后完成。
3. **诊断手段（已留在代码里，`DbgLog` 系列）**：
   - `DbgLog` → `%TEMP%\AIPTool_debug.log`（ctor / Activate 各阶段 / CreatUI 起止 / Deactivate / ProcessExit / DomainUnload / 未处理异常）
   - `DbgEventListener`（继承 `EventListener`，订阅 `Microsoft-Windows-DotNETRuntime`，Verbose）→ 记录进程内**所有 first-chance 托管异常**，这是定位此类"无日志闪退"最有效的手段
   - 已验证 Inventor 进程内本身就跑着 .NET Framework 托管代码（`InvAppHome`、`Autodesk.DesktopConnector.API`），与我们的 .NET 8 运行时并存；日志里大量 `FileNotFoundException`/`BadImageFormatException` 都是 Inventor 自身/其他插件的已捕获异常，不是问题
4. **验证方法**：把 `Autodesk.AIPTool.Inventor.addin` 改名成 `.disabled` 再启动 Inventor，能起来就说明是插件问题；排查 COM 激活用 `cscript` + `CreateObject`。
5. 已开启 WER LocalDumps：`HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\Inventor.exe` → DumpFolder `D:\Temp\Dumps`（调试器下不一定产出）。
