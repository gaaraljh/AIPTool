## 新增「外观」列（cApp）功能
- 在 `Class/clsBomTool.vb` 的 BOM 工具「列管理」中新增内置列 **外观 (Appearance)**，列名 `cApp`，完全参照 `cMat`（材料）列的模式实现。
- 实现要点：
  - `BomDataRow.Appearance` 字段；BOM 采集时（`CollectRows`）从 `PartDocument.ActiveAppearance.DisplayName` 读取（仅零件文档；装配体无单一外观，留空）。
  - 新增 `LoadAppearanceList()`，从 `ThisApplication.AssetLibraries(i).AppearanceAssets` 填充外观列下拉（含当前 BOM 已有外观 + 外观库）。
  - `BuildGridColumn` 为 cApp 生成 `DataGridViewComboBoxColumn`。
  - 写入时（`FastWriteRow` 与 `OnWriteClick`）若 `cApp` 被修改且为零件文档，遍历外观库匹配 `DisplayName` 并设置 `partDoc.ActiveAppearance = app`（与材料 ActiveMaterial 完全隔离）。
  - 列管理「添加列」下拉加了「外观 (Appearance)」，选它会转调 `RestoreBuiltinCol("cApp")`。
  - 已同步导出/导入 Excel（列名 `Appearance`）、`GetRowPropVal`、缺失属性检查等。
- 注意：外观是 Inventor 的 Asset，不是 iProperty 字符串；装配体级别不写外观（与「更改当前零件外观」需求一致）。

## 编译错误修复（外观列改动）
- `clsBomTool.vb` 实际上**会被编译**：vbproj 里 `<Compile Remove="clsBomTool.vb" />` 因文件在 `Class\` 子目录、路径不匹配而失效（Remove 用的是无路径名）。不要被该 Remove 误导，改此文件会进入编译。
- 初版「外观」改动在 `OnWriteClick` 与 `FastWriteRow` 两处写入块插入时，把 cApp/cMat 块收尾的 `End If` 吞掉，导致 BC30081/BC30087/BC30380/BC30383 等 "If/End If/Catch/End Try 不匹配" 错误。已用正则删除 OnWriteClick 的两行损坏代码、并给 FastWriteRow 补回缺失的 `End If`，重新编译通过（仅剩无关的 SYSLIB0014 WebClient 过时警告）。
- 教训：在该文件插入大段嵌套 Try/If 块时，务必核对每个 `If`/`Try` 都有对应 `End If`/`End Try`。

## 修复：编辑单元格后属性未真正落盘（自动写入失效）
- 现象：用户改图号/材料/描述/外观/自定义属性等列后，零件文件没被修改。
- 根因：`OnCellValueChanged`(L7416) 对除 cFile 外的列调用 `FastWriteRow`(L8021)；`FastWriteRow` 只把属性值写到**内存中的文档对象**，除 BOM 结构分支外**从不调用 `tDoc.Save()`**。只有「零件代号(cPno)」列走了独立的 `OnCellLeave_Pno`(L7349) 并显式 `tDoc.Save()`(L7406)，所以仅该列会保存。
- 修复：在 `FastWriteRow` 写属性后补 `If tDoc IsNot Nothing AndAlso tDoc.IsModifiable Then tDoc.Save()`；同样给未接按钮的 `OnWriteClick`(L8289) 每行补 Save 以保持一致。
- 同步修正使用说明文案（L6582/6588/6603 原称「点底部写入属性按钮」，已改为「编辑单元格后自动保存」）。
- 注：工程内并不存在「写入属性」按钮，原说明是过时文案；当前为「编辑即自动保存」模式。若以后想恢复显式按钮，需在底部工具栏 `pnlBottom` 加按钮并 `AddHandler ... OnWriteClick`。

## 优化：改材料/外观后零件卡在"需要更新/报错"
- 现象：在 BOM 工具里改材料(cMat)或外观(cApp)后，零件不刷新、浏览器显示"需要更新"和报错图标，点更新/报错无反应，只能关软件重读才正常。
- 根因：`FastWriteRow` 只设置 `partDoc.ActiveMaterial` / `ActiveAppearance`，未触发零件重建与视图刷新；当该零件是装配体组件时，Inventor 把它标成"需要更新"且特征报错状态未被清除。
- 修复：在 `FastWriteRow`（及 `OnWriteClick` 保持一致）材质/外观写入后，强制 `pDoc.Update()` + 遍历 `pDoc.Views` 调 `vw.Update()`，并同步 `g_asmDoc.Update()` 与 `ThisApplication.ActiveView.Update()`，全部包在 Try/Catch 中（避免罕见特征报错中断工具）。顺序：先 Update+刷新，再 Save。
- 变量：`g_asmDoc` 是顶层装配体文档（AssemblyDocument，clsBomTool.vb L271/L6159）。

## 改为「编辑暂存 + 写入属性按钮提交」模式
- 用户决定：编辑单元格不再自动落盘，改由底部工具栏新增的「写入属性」按钮（OnWriteClick）统一提交保存。
- 改动：
  1. `FastWriteRow`：删除自动 `tDoc.Save()` 块、删除 BOM 批量保存（`g_pendingSaveDocs` 那段）、删除 `bomRow.ChangedCols.Clear()`。编辑仅写入内存 + 材质/外观 `Update` 即时预览，不保存，保留 `ChangedCols` 供按钮提交。
  2. `OnCellLeave_Pno`（零件代号列）：删除其独立的 `tDoc.Save()`，改为仅预览（与全局一致）。
  3. `OnWriteClick`：提交后 `For Each _r As BomDataRow In g_rows : _r.ChangedCols.Clear() : Next` 清空修改标记，供后续增量编辑重新累计。OnWriteClick 内含真正的 `Save` + 材质/外观 `Update`+刷新。
  4. `pnlBottom`：在 `btnAutoAll` 后新增分隔符 `sepW` 与绿色按钮 `btnWriteAttr`（文字「写入属性」，`AddHandler btnWriteAttr.Click, AddressOf OnWriteClick`）。
  5. 同步更新「使用说明」文案（L6582/6588/6603）改为"点写入属性按钮保存"。
- 注意：`ChangedCols` 是关键开关——编辑时累计、FastWriteRow 不再清空、OnWriteClick 提交后清空；OnWriteClick 靠它筛选需写入的行。
- 设计权衡：为一致性，连「零件代号」列也改为仅预览、由按钮保存（之前它独立自动保存）。如用户想让某列仍自动保存，需单独保留其 Save。

## 最终决定：回退为「编辑即自动写入」，删除「写入属性」按钮
- 用户最终选择：`还是改成自动写入，并删除写入属性这个按钮`。即把上一轮（加按钮/去掉自动 Save）的改动整体回退。
- 回退内容：
  1. `FastWriteRow` 恢复：`tDoc.Save()` 块 + `bomRow.ChangedCols.Clear()` + BOM 批量保存（`g_pendingSaveDocs` 那段）→ 编辑即自动落盘。
  2. `OnCellLeave_Pno`（零件代号列）恢复独立 `tDoc.Save()`（与自动写入一致）。
  3. `pnlBottom` 删除 `btnWriteAttr` 按钮、`sepW` 分隔符、`AddHandler ... OnWriteClick`。
  4. `OnWriteClick` 删除提交后 `ChangedCols.Clear()` 循环（恢复为遗留死代码，无按钮绑定）。
  5. 说明文案改回"编辑单元格后自动写入零件文件（无需额外按钮）"。
- 保留的修复：材质/外观变更后的 `pDoc.Update()` + 视图刷新 + `g_asmDoc.Update()` 仍留在 `FastWriteRow`（解决之前"需要更新/报错卡死"问题）。
- 结论：当前为「编辑任意列即自动写入并保存」模式；`OnWriteClick` 再次成为无绑定的遗留子过程。
